All hosted warm-sidebar groups exceed the initial 200 ms feedback target and
700 ms content-frame p95 target. Feedback generally arrives with content; there
is no workspace loading boundary. The frame metric is only a proxy for usability.

First-observed RSC headers have hosted warm-sidebar medians of 180–213 ms,
versus 24–35 ms locally. **Headers are not full destination data.** Most observed
RSC bodies were cancelled rather than completed; Next can consume required
streamed data before cancellation. Missing completion metrics stay missing.
Prefetch and multiple streams also prevent treating the first RSC as the sole
critical response.

The next observed CDP Paint after sampled DOM readiness has hosted warm-sidebar
p95 of 4–25 ms, and local p95 of 6–15 ms. No >50 ms long tasks were observed in
these warm-sidebar groups. This does not rule out the user's reported rendering
delay in other interactions or establish the response-completion-to-paint budget.
Other exploratory groups include occasional 51–57 ms long tasks and a populated
Settings first-visit outlier of 3211 ms; neither should be hidden by warm summaries.

## Provider-count evidence

Local observed navigation RSC requests for Tasks and Calendar correlated with
one outbound profile read and zero `/auth/v1/user` calls per sample. This applies
to sibling transitions, not initial layout entry or the independent proxy auth
boundary. Repeated context calls in source do **not** establish repeated outbound
requests. Initial entry and hosted counts still require evidence before retaining
a request-memoization optimization.

## Ranked hypotheses and next experiments

1. **Server/streaming work and deployment distance:** hosted totals substantially
   exceed local totals, and functions/database are on different continents.
   Correlate provider waterfalls and required stream arrival first. Region
   mismatch is a candidate, not a proven attribution or authorization to move it.
2. **Missing immediate destination feedback:** source has no route loading
   boundary, and observed feedback waits for content. Story 09-03 tests a loading
   boundary separately, preserving completed-screen geometry and auth semantics.
3. **Calendar independent read waterfall:** source awaits subjects before
   occurrences. Trace actual sequential durations, then test parallelization in
   09-02 without changing recurrence/range/ownership rules.
4. **Client/React work:** warm traces do not show sustained main-thread blockage.
   Measure date/view changes and detail/mutation readiness before deciding on
   component changes or a conditional JSON-query migration.
