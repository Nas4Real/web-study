# Cloudflare R2 private bucket

Web Study stores file bytes in one private R2 bucket. Postgres remains the authority for ownership, metadata, status, and quota accounting. The bucket must not expose an `r2.dev` public URL or public custom domain.

## Credentials

Create an R2 S3 API credential scoped to the Web Study bucket and provide its account ID, access key ID, secret access key, and bucket name through the server-only environment variables in `docs/ENVIRONMENT.md`. Never paste credentials into this file, browser code, logs, or CI output.

The adapter uses Cloudflare's account endpoint with AWS SDK v3 region `auto`:

```text
https://<R2_ACCOUNT_ID>.r2.cloudflarestorage.com
```

## Browser CORS policy

Presigned URLs authenticate an individual operation, but browsers still require bucket CORS. Add the following policy in the bucket's **Settings → CORS Policy → JSON** editor, replacing the example production origin with the deployed app's exact origin:

```json
[
  {
    "AllowedOrigins": [
      "https://study.example.com",
      "http://localhost:3000"
    ],
    "AllowedMethods": ["GET", "PUT", "HEAD"],
    "AllowedHeaders": ["Content-Type"],
    "ExposeHeaders": ["ETag", "Content-Length"],
    "MaxAgeSeconds": 3600
  }
]
```

- Use exact origins with no path or trailing slash. Do not use `*` for this private application.
- Keep `DELETE` out of CORS; physical deletion is server-only.
- Add a local origin only for ports actually used by the development app.
- The client must send the same `Content-Type` value bound into the presigned PUT signature.
- CORS changes can take about 30 seconds to propagate.

Cloudflare references:

- Presigned URLs and AWS SDK v3: https://developers.cloudflare.com/r2/api/s3/presigned-urls/
- Browser CORS configuration: https://developers.cloudflare.com/r2/buckets/cors/

## Runtime contract

- Object keys are immutable and opaque: `users/{user_id}/files/{file_id}`.
- Upload and download URLs expire in at most 10 minutes and are bearer capabilities; never log them.
- Upload signatures bind the exact object key and `Content-Type`.
- Browser uploads are single PUT requests. HEAD verification and deletion use server credentials through the adapter.
